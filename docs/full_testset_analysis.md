- 数据路径：`D:\Industrial-Surface-Defect-Inspection\data\raw\test`

- OK 数量：894（mask 全黑）

## 4. GT 缺陷面积分析

| 指标 | TP (n=5) | FN (n=105) |
|------|----------|------------|
| 平均 GT 缺陷面积 | 2,877.2 | 4,496.0 |
| 平均 GT 缺陷比例 | 1.97% | 3.11% |

**关键发现**：TP 样本的平均 GT 缺陷面积（2,877）反而小于 FN 样本（4,496）。这说明漏检的主要原因不是缺陷面积太小，而是**缺陷的灰度对比度不够**——固定阈值方法对低对比度缺陷不敏感，即使缺陷面积大，如果灰度与背景接近，也难以被阈值分割出来。

## 6. Precision 与 Recall 的取舍

实验结果清晰展示了工业缺陷检测中的经典权衡：

- **高 Recall 路线**（gray=60, area=20）：检出全部 110 个缺陷，但同时也将 853 张 OK 误判为 NG，Precision 仅 11.4%
- **高 Precision 路线**（gray=200, area=100）：一张 OK 都不误判，但只检出 5/110 个缺陷，Recall 仅 4.5%

工业场景中：
- 漏检（FN）可能导致缺陷零件流入下游，造成质量事故——通常更严重
- 误检（FP）导致不必要的产线停机和人工复检——增加运营成本
- 最优参数取决于产线容忍度：是漏检成本高，还是误检成本高？

## 8. 当前 OpenCV 方法局限

- **固定阈值对低对比度缺陷不敏感**：FN 样本的平均 GT 面积（4,496）大于 TP（2,877），但仍被漏检——核心问题是灰度对比度而非面积
- **对复杂纹理鲁棒性有限**：背景纹理变化可能被误识别为缺陷
- **不同数据分布需要重新调参**：模拟图片上 100% Recall，真实数据上仅 4.5%
- **仅靠面积阈值不够稳定**：真实缺陷的检测瓶颈在分割阶段，而非面积判断
- **Otsu/Adaptive 也没有显著改善**：虽然 Recall 达到 100%，但 FP 爆炸（894 张 OK 全被误判）

## 9. 后续改进方向

- **更强的局部增强**：CLAHE、同态滤波等增强缺陷与背景的对比度
- **基于 mask 的像素级评价**：使用 GT mask 直接评估分割质量（IoU、Dice）
- **连通域特征过滤**：基于面积、长宽比、圆形度过滤 FP
- **级联检测**：先用敏感参数检测候选区域，再用特征过滤
- **YOLO 目标检测训练**：标注真实缺陷，从根本上解决对比度问题
- **分割模型**：U-Net 等像素级分割方法替代阈值分割
