# 面试常见问题与回答

## 1. 为什么先做 OpenCV 而不是直接上 YOLO？

OpenCV 可以做快速 baseline，验证数据集的质量和问题的难度。而且传统方法的每一步都是可解释的——灰度化、阈值、形态学——这对理解缺陷检测的底层逻辑很有帮助。直接上 YOLO 虽然效果好，但你可能不知道为什么好。

## 2. 为什么用 CLAHE？

V1.1 的固定阈值在真实数据上 Recall 只有 4.5%，因为缺陷和背景的灰度对比度太低。CLAHE 做局部对比度增强，让暗区域的缺陷被"提亮"，F1 直接从 0.087 跳到 0.688。

## 3. 为什么要用 mask，不只是 OK/NG 标签？

KolektorSDD2 数据集提供了像素级 GT mask。mask 可以做两件事：一是 YOLO segmentation 训练（比 detection 更精细），二是像素级的 IoU/Dice 评价。只用 OK/NG 标签就浪费了这个信息。

## 4. 为什么用 YOLO segmentation 而不是 detection？

数据集的 GT mask 是像素级的，缺陷形状不规则，bounding box 会包含大量背景。segmentation 直接预测缺陷形状，评价更准确。

## 5. 为什么 10 epochs 不如 3 epochs？

CPU 训练 batch=2，训练不稳定。更多 epoch 导致模型在训练集上过拟合，FP 从 9 涨到 17。这在小数据集 + 小 batch 场景下很常见。

## 6. Precision / Recall / F1 怎么理解？

- Precision = TP/(TP+FP)：检出的缺陷中，有多少是真的缺陷
- Recall = TP/(TP+FN)：所有真实缺陷中，检出了多少
- F1 = 两者调和平均，平衡 Precision 和 Recall

## 7. FP / FN 在工业中哪个更严重？

通常 FN（漏检）更严重，因为缺陷产品会流入下游。FP（误报）会导致不必要的复检，增加成本，但不会造成质量事故。不过这取决于具体产线——有些产线误报停线成本也很高。

## 8. 为什么 conf=0.03 和 0.05 都有意义？

- conf=0.05：F1 最高（0.833），平衡方案
- conf=0.03：Recall 80.9%，适合对漏检容忍度极低的场景

选择哪个取决于产线对 FN 和 FP 的成本评估。

## 9. 项目的数据集多大？够用吗？

3335 对图像，其中 NG 只有 356 张。对于深度学习来说偏小，但 smoke training 已经可以得到 F1=0.833。正式训练需要更多数据或数据增强。

## 10. 这个项目的局限是什么？

最主要的局限是 CPU 训练不够充分。3 个 epoch 远未收敛，真正的潜力需要 GPU 训练来释放。其他局限包括数据集规模有限、仅做了图像级评价、没有部署方案。

## 11. 后续如何提升？

- GPU 训练 50+ epochs，更大 batch
- 换用 yolov8s-seg 或更大模型
- 数据增强
- 像素级分割评价
- 导出 ONNX 并做推理加速

## 12. 项目中你遇到的最大困难是什么？

最大的困难是发现固定阈值方法在真实数据上完全不行——模拟图片上 100% 准确率，真实数据只有 4.5%。这让我意识到传统方法的天花板，也促使我转向 CLAHE 和 YOLO。

## 13. 为什么用 yolov8n-seg 而不是更大的模型？

nano 模型参数最少（3.2M），在 CPU 上训练可行。更大模型需要 GPU。

## 14. 项目的工程化程度如何？

有 tkinter GUI、CSV 报表自动保存、Matplotlib 实验图表、完整的 Git 版本管理（14 个 release tag）、README 和文档体系。

## 15. 你是怎么处理数据不平衡的？

NG 只有 356 张，OK 有 2979 张。在 YOLO 训练中使用默认的类别权重，没有做专门的重采样——这也是 Recall 还没到 90%+ 的原因之一。

## 16. 你是怎么做参数调优的？

OpenCV 端做了 100+ 组网格搜索；YOLO 端做了 6 个 confidence 的 sweep。所有实验结果都存了 CSV，用 Matplotlib 做了可视化。

## 17. 如果给你一张新的缺陷图，你会怎么处理？

先用 CLAHE 增强→OpenCV 检测做快速判断，如果结果不确定，再用 YOLO 模型推理看 mask。两者的结果可以做交叉验证。

## 18. 你对工业缺陷检测的理解是什么？

工业缺陷检测的核心挑战不是"能不能检测"，而是"能不能在极低 FN 的前提下控制 FP"。产线上一分钟可能过几百个零件，FP 太高产线会不断停机。

## 19. 你在这个项目里学到了什么？

最大的收获是理解了从传统方法到深度学习的完整演进路线。OpenCV→CLAHE→YOLO，每一步都有明确的动机——不是因为深度学习"更高级"，而是因为前一步确实遇到了无法突破的天花板。

## 20. 如果重新做这个项目，你会怎么改进？

第一件事就是上 GPU 训练。3 个 epoch 的 YOLO 已经比 CLAHE 好这么多，50 个 epoch 会好多少我很好奇。另外我会在数据准备阶段就用上数据增强，而不是等到训练时再想。
